# B1. Solution design

> **Outline.** The material of this module is being written by the Showcase and Certification Working Group. The objectives, outline and assessment below are the agreed scope for program version 2026.1.

8 class hours. Assessed by: case study.

## Learning objectives

After this module you can:

1. Map a use case to ecosystems, schemas, roles, onboarding modes and fees, and justify each choice.
2. Reuse the four playground patterns (Vesta, Verandia, CEXA, BHI) and know when each applies.
3. Decide what stays off chain, what is a credential, what is an accreditation, and what is a digest.
4. Write a solution design document a buyer and an engineer can both read.

## Prerequisites

C1, C2, C3, C4.

## Outline

### 1. Method

From actors and claims to schemas; from authority to ecosystems and validators; from risk to modes, periods and slashing; from volume to fees.

### 2. The four patterns

Vesta (a service proves itself); Verandia (login and age with a government-style credential); CEXA (reusable KYC and KYB across exchanges, controller as sole issuer); BHI (badges and sector accreditation).

### 3. Boundaries

Data minimization; what never goes on chain; where fiat and off-chain contracts fit; integrating with existing identity providers.

### 4. The design document

Template: context, actors, trust questions, ecosystems and schemas, roles, fees, rollout, risks; diagrams that match the playground's.

## Assessment

Case study: a design document for a use case drawn by the certificator, graded against the rubric.

## Reading list

Playground use cases and their diagrams. docs.verana.io: Understand (all). The Verana use-case analyses published by the Foundation.
